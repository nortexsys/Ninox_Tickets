## S22 timings (close-adr-011 task 5.5) — done

* Galaxy S22 (SM-S901B, Android 16) linked by wireless adb. Debug build, `pdf_text_eval_test.dart` over the
  8 PDFs of the private corpus (6 invoices, 2 synthetic), read through the shipped pdfrx adapter.
* **9 pages: median 8 ms, mean 12.3 ms, max 37 ms** per page (emulator median was 17 ms). The two slowest
  pages are the first reads of the run (23 ms, 37 ms), so a cold start costs more than steady state.
  Input hash unchanged in 8 of 8. Debug build: a release build may be faster.
* Output kept in the private corpus (`out/adr011-s22/`); the PDFs and results were removed from the phone.
* Lesson: `flutter test` on a device uninstalls the app and its data at the end; use `--no-uninstall`
  when results must be pulled afterwards. Git Bash needs `MSYS_NO_PATHCONV=1` for Android paths.

## Device check of `implement-android-capture-and-store` (T1.12–T1.13), design §4 — passed

Galaxy S22 over wireless adb, debug build, synthetic PDF `demo-invoice.pdf` generated by
`corpus_test/src/make_demo_invoice.py` (never a corpus file). The PO operated the phone; the orchestrator
read the stored files with `run-as` and compared SHA-256.

| Check | Result |
| --- | --- |
| Scan a two-page document | One scanner session → one PDF with 2 pages (`/Count 2`), 1,060,899 bytes; the hash the app shows equals the hash of the stored file |
| Pick a PDF | Stored original byte-identical to the source: 3,167 bytes, same SHA-256 |
| Share a PDF from another app | Same result as the picker |

* Not a defect, but worth knowing: two scans started separately are two documents. Pages of one document are
  added with "+" **inside** the scanner before saving. Two documents received separately are not merged (not in M1).
* The same file received twice gets two folders (the `docId` is content-free by design); duplicate detection is not part of this change.
* The wizard opens on a device with no destination and asks for a token. The check ran on a temporary entry
  point that skips that question (`hasDestination: () async => true`), not committed and now deleted; the real
  wizard was **not** exercised and nothing was written to Ninox.
* Two traps for the next device session: an APK left by `flutter test --no-uninstall` has the test listener
  as its `main` (black screen with the logo); rebuild with `flutter build apk --debug -t lib/main.dart`.
  The wireless-adb connect port changes whenever the wifi or the setting is toggled.
