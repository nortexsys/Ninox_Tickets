## Lessons for the next session

* Wireless adb pairing is **per wifi network**. After a network change run `adb pair` (the user does it, the
  code stays with them), then `adb connect`. The connect port changes whenever the service restarts: read it
  from `adb mdns services`.
* `flutter test` of an `integration_test/` file has a 30 s default timeout: pass `--timeout 20m`. Use
  `--no-uninstall` when data must survive. Reinstall the normal build afterwards
  (`flutter build apk --debug -t lib/main.dart`, then `adb install -r`).
* On Windows `adb` does not understand `/c/...` paths: `cd` to the folder and push with relative names.
* A lane runner holds one worktree per role. Before starting a new change on a role, remove the old worktree
  (`git worktree remove`) and delete the merged branch; the branch of a change that is not merged must be kept.
* A runner verdict of `reject` caused only by `openspec/` files or by `main_checkout_changed` (the
  orchestrator running Flutter in the main checkout during a lane) is not a lane defect; read `outside_writes`.
* A lane can die silently (no report, no commit): check whether it left files, then `--resume`. A
  `UnicodeDecodeError` from a reader thread in the log does not stop it.
