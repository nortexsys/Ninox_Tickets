## Incident — live Ninox reads without the PO's approval

While reviewing Ninox's T1.8 delivery, the orchestrator ran `dart test packages/ninox_client` from the
repository root in its own shell. The package's `dart_test.yaml` (which skips the `live` tag) is not
read from there, and the orchestrator's shell carries `NINOX_API_KEY` from the user environment, so
the GAP-023 check **ran twice against the test base** (team `qCq3JS7q7ptoap8Yg`, database
`db0000000000`, both explicit in the test). It issues `listRecords` GETs only — verified by reading
the test — and wrote nothing. It was still a use of the token without the PO's approval
(`AGENTS.md` §1.5 covers writes; the plan requires approval for any lane live call, and the
orchestrator holds itself to the same). Corrective action: the live test is being changed to skip
unless an explicit opt-in variable is set, checked inside the test file; the orchestrator runs Dart
tests from each package's folder from now on.

**What it measured (GAP-023):** with `order=sequence` and `desc=true` the API returned record 440123
before 440126 — the list was **not** sorted descending. On this evidence `order`/`desc` cannot be
relied on, and the reconciliation must page through recent records and sort in memory. To be recorded
in GAP-023 by Spec, and confirmed by the approved T1.9 run.
